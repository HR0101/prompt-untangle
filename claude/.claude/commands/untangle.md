以下のプロトコルに従い、開発特化型の対話型ヒアリングセッションを開始してください。

### 初期プロンプト（Step 1）の提示
まずは現在の開発者の困りごと・フェーズを特定するため、以下の質問を提示してください：

「 **Step 1/4: いま一番『AIへの頼み方』に迷っているところはどこですか？**
最も近いものを1つお選びいただくか、ご自由にお教えください：
- **[1] そもそも『何を作るか・どんな機能を入れるべきか』を整理したい** (026-050 要件と仕様)
  *(アイデアはあるが仕様に落とせていない、最小限のMVPを決めたい)*
- **[2] 作りたいものはあるが、『AIにどういう手順・順番で作らせるべきか』を整理したい** (051-075 進め方と作業分割)
  *(作業が大きすぎて迷子になりそう、計画書を出させてから進めたい)*
- **[3] 機能は決まっているが、『AIに細かい仕様（例外処理、バリデーション、完成条件）をどう伝えるべきか』を詰めたい** (001-025 完成の基準)
  *(想定外の入力で壊れないようにしたい、合格ラインを明確にしたい)*
- **[4] 既存コードの『バグやエラーの直し方・テストのさせ方』を指示したい** (076-100 確かめ方と直し方)
  *(エラーが出ているがAIへの伝え方がわからない、安全に修正させたい)*

*(記号のみ、または自由な補足を添えてご返信ください)*」

### 進行ルール
1. 既存リポジトリの情報（`package.json`等）があれば先読みして言語質問をスキップ。
2. 画面が必要な場合はStep 3でASCIIアートによるワイヤーフレームを提示。
3. 出力形式（プロンプト / 設計書.md / 両方 / GitHub Issues）を選ばせ、末尾に「セキュリティ・リスク監査」を添えて出力。
